# Личный кабинет команды — настройка и деплой

Новый, отдельный контур: Vercel Serverless Functions (`/api/**`) + Postgres.
Не связан со старой рассылкой (Airtable + n8n, ветка
`claude/n8n-messenger-broadcast-q49ox0`) — та продолжает работать как есть.

## Что это

- `kabinet-zayavka.html` — заявка на подключение (имя + email)
- `kabinet-glavnaya.html` — личный кабинет участника: сигналы на сегодня,
  статистика, заработок, выводы
- `kabinet-admin.html` — админка Ольги: одобрение заявок, уровни/ставки,
  слоты сигналов, ввод дневных кодов, доступ участник↔слот, курс/комиссия
- `kabinet-vhod.html` — страница-заглушка при невалидной/просроченной ссылке
- `manifest.json` + `sw.js` — PWA-обвязка (кабинет можно установить на
  телефон как приложение)
- `api/**` — бэкенд (Node.js, обычные Vercel Serverless Functions)
- `db/migrations/001_init.sql` — схема БД
- `scripts/create-admin.js` — разовый скрипт создания первого администратора

## Шаг 1 — база данных

1. В Vercel Dashboard → проект → Storage → Create Database → **Postgres**.
   Vercel сам подставит переменные окружения (`POSTGRES_URL` и т.д.) в
   проект — ничего вручную копировать не нужно.
2. Примените схему:
   ```bash
   vercel env pull .env.local   # подтянет POSTGRES_URL и остальные переменные
   psql "$(grep ^POSTGRES_URL= .env.local | cut -d= -f2-)" -f db/migrations/001_init.sql
   ```
   (Либо выполните содержимое файла через встроенный Query-редактор в
   Vercel Dashboard → Storage → ваша БД → Query.)

## Шаг 2 — первый администратор

Некому одобрять заявки, пока нет ни одного администратора — создаём его
напрямую скриптом:

```bash
npm install
POSTGRES_URL="..." SITE_ORIGIN="https://ваш-домен" \
  node scripts/create-admin.js "Ольга" olga@example.com
```

Скрипт выведет **постоянную персональную ссылку** для входа в
`kabinet-admin.html` — сохраните её, она не логируется и не показывается
повторно. Перейдите по ней — попадёте в кабинет с ролью администратора
(сама главная страница кабинета `kabinet-glavnaya.html` доступна
администратору так же, как обычному участнику; админка — по отдельной
ссылке `kabinet-admin.html`).

## Шаг 3 — базовая настройка в админке

Перед тем как участники начнут пользоваться кабинетом:

1. **Уровни** — создайте хотя бы один уровень со ставкой USDT за сигнал
   (например, «Базовый» — 12 USDT).
2. **Слоты сигналов** — создайте нужные слоты (расписание пока не
   настраивается через интерфейс — поле `schedule` зарезервировано в БД
   под будущее автоматическое расписание, когда оно будет прислано).
3. **Курс и комиссия** — задайте текущий курс USDT→RUB и комиссию на
   вывод (по умолчанию 30%). Курс нужно обновлять вручную по мере
   изменения — автоматическое обновление по API не входит в v1
   (см. план, раздел «Явно вне scope»).

## Шаг 4 — подключение участников

1. Участник заходит на `kabinet-zayavka.html`, оставляет имя и email.
2. Заявка появляется в `kabinet-admin.html` со статусом «pending».
3. Ольга нажимает «Одобрить» — заявка переходит в «active», админка
   показывает постоянную персональную ссылку для входа. **Эта ссылка не
   логируется и не сохраняется системой в открытом виде** (в БД — только
   её хэш) — передайте её участнику лично или на email прямо сейчас, пока
   не закрыли страницу.
4. Назначьте участнику уровень (раздел «Участники» → выбрать в списке
   уровней) и доступ к нужным слотам сигналов (раздел «Доступ участника
   к слотам»).

## Rate limiting (опционально, но рекомендуется)

`POST /api/auth/signup` и `GET /api/auth/enter` защищены самодельным
rate-limit'ом. Без дополнительной настройки он работает «в памяти» одного
serverless-инстанса — не строгая защита. Чтобы получить честный лимит:

1. Vercel Dashboard → Marketplace → **Upstash Redis** → подключить к проекту
   (бесплатного тарифа достаточно для старта).
2. Переменные `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`
   подставятся в проект автоматически — код их подхватит без изменений
   (`api/_lib/ratelimit.js`).

## Проверка после деплоя

```bash
# Заявка на подключение
curl -s -X POST https://ваш-домен/api/auth/signup \
  -H 'Content-Type: application/json' \
  -d '{"name":"Тест Тестов","email":"test@example.com"}'

# После одобрения в админке — переход по персональной ссылке должен
# создать сессию и отредиректить в kabinet-glavnaya.html:
curl -sI "https://ваш-домен/api/auth/enter?token=ВАШ_ТОКЕН"

# Admin-эндпоинты без сессии администратора должны отвечать 401/403:
curl -s -o /dev/null -w '%{http_code}\n' https://ваш-домен/api/admin/users
```

## Важно про постоянную ссылку-вход

Ссылка не истекает сама (в отличие от обычной magic-link) — переход по ней
создаёт обычную браузерную сессию (HttpOnly cookie), и дальше участнику не
нужно переходить по ссылке заново на одном устройстве. Если ссылка могла
кому-то попасться на глаза — участник (или админ за него, через
`kabinet-admin.html` → повторное «Одобрить» перевыпустит ссылку) может
перевыпустить её кнопкой «Перевыпустить мою ссылку» в кабинете — старая
сразу перестаёт работать.

## Вне scope v1

Реальные платежи (вывод — учётная запись факта, не перевод денег),
автоматическое обновление курса USDT→RUB по внешнему API (поле в БД уже
готово это принять), нативное мобильное приложение (только PWA), миграция
старой рассылки на эту систему, точное расписание сигналов (придёт позже —
модель данных `signal_slots.schedule` уже готова его принять).
